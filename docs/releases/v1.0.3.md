# StudyOrganizer v1.0.3

This release adds an administrator-creation command and fixes production
Filament access and Laravel HTTP startup behind a reverse proxy.

## Administrator provisioning

```bash
php artisan admin:create
```

For a deployed container using the documented Compose helper:

```bash
dc exec --user www-data web php artisan admin:create
```

The command prompts for name, email, a hidden password of at least 12 characters,
and confirmation. It assigns the admin role and hashes the password. Existing
email addresses are rejected without changing the account. Name/email flags
are available; no password flag is provided.

## Production fixes

- Admin-role users can access Filament in production; student/professor roles
  remain blocked. The generic Filament user command still uses the database's
  default student role, so use `admin:create` for new administrators.
- Proxy trust is loaded after Laravel bootstrapping and supports config caching.
- Tinker uses a writable configuration directory for the container's app user.
- Native HTTP defaults to loopback port `3060`; PostgreSQL host access defaults
  to loopback `3062`, while application database connections remain on `5432`.

## Deployment

Rebuild and publish an image tagged `1.0.3`, update `APP_IMAGE` locally on the
deployment host, and recreate the enabled application services. The GitHub
release contains source; it does not automatically publish a container image.
Preserve existing Laravel keys, database passwords, uploads, and database volumes.

The developer, Docker production, and release guides cover Compose selection,
HTTPS proxy integration, migrations, backups, account management, diagnostics,
and versioned publishing. All configuration examples use placeholder addresses;
real credentials and deployment settings are excluded from the release files.
